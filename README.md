# Калькулятор начинки — Telegram Mini App

Считает граммовки начинки под форму и количество конфет, с учётом слоёв,
доли корпуса и запаса на потери. Работает как Mini App внутри Telegram.

## Что внутри

```
server.js      Express: API, статика, вебхук бота
db.js          Postgres: схема и доступ к данным
auth.js        Проверка подписи initData от Telegram
bot.js         Бот: /start и разбор пересланных рецептов
parser.js      Разбор рецепта из текста (общий для бота и приложения)
public/        Клиент, один самодостаточный HTML
```

Данные лежат одним JSON-документом в таблице `app_state` с полем `rev`.
Для одного кондитера с помощниками этого достаточно, а схема меняется
без миграций. Когда пользователей станет больше десятка или понадобится
искать по рецептам запросами, разделы стоит разнести по обычным таблицам.

Картинки лежат отдельно в таблице `files` и отдаются по `/api/img/:id`,
чтобы документ состояния не распухал.

## Развёртывание

### 1. Бот в BotFather

1. `/newbot` → имя и username → получите **токен**.
2. Токен больше нигде не светите: он лежит только в переменных Railway.

### 2. Репозиторий

Залейте эту папку в GitHub. Файл `.env` в репозиторий не кладите,
`.gitignore` уже это учитывает.

### 3. Сервис на Railway

1. **New Project → Deploy from GitHub repo**, выберите репозиторий.
2. **New → Database → Add PostgreSQL**. Переменная `DATABASE_URL`
   пропишется сама.
3. В сервисе откройте **Settings → Networking → Generate Domain**.
   Получите адрес вида `имя.up.railway.app`.
4. В **Variables** добавьте:

   | Переменная | Значение |
   |---|---|
   | `BOT_TOKEN` | токен из BotFather |
   | `ADMIN_IDS` | ваш Telegram ID, можно несколько через запятую |
   | `WEBHOOK_SECRET` | любая случайная строка |
   | `PUBLIC_URL` | `https://имя.up.railway.app` |

   Свой ID можно узнать у бота `@userinfobot`.

5. Дождитесь деплоя. В логах должно появиться «база готова»,
   «слушаю порт» и «вебхук установлен».

### 4. Привязка Mini App

В BotFather:

- `/newapp` → выберите бота → заполните название и картинку →
  в поле **Web App URL** укажите `https://имя.up.railway.app`
- `/setmenubutton` → выберите бота → тот же URL → название кнопки,
  например «Калькулятор»

Откройте бота, нажмите `/start` → «Открыть калькулятор».

### 5. Первый запуск

Первый администратор, открывший приложение, зальёт стартовый набор:
четыре формы, три начинки и примеры конфет. Дальше всё правится
из интерфейса.

## Проверка после деплоя

- `https://имя.up.railway.app/healthz` отвечает `{"ok":true}`
- в браузере приложение открывается, но пишет «откройте приложение
  из Telegram» — так и должно быть, подписи нет
- в Telegram открывается и считает
- перешлите боту сообщение с рецептом — он ответит разбором

## Права доступа

Подпись `initData` проверяется на сервере при каждом запросе.
`initDataUnsafe.user.id` с клиента не используется нигде: его
подделать элементарно.

Проверка администратора стоит на записи (`PUT /api/state`,
`POST /api/img`) и на сохранении рецептов через бота. Спрятать
кнопки в интерфейсе — это удобство, а не защита.

Список администраторов лежит в таблице `admins`. При старте туда
добавляются ID из `ADMIN_IDS`. Убрать администратора можно только
запросом к базе — экрана для этого пока нет:

```sql
delete from admins where tg_id = 111111111;
```

## Локальный запуск

```bash
npm install
export DATABASE_URL=postgres://localhost/praline
export ALLOW_DEV_ADMIN=1
npm start
```

`ALLOW_DEV_ADMIN=1` пускает без Telegram с правами администратора.
На продакшене эту переменную задавать нельзя.

## Что осталось за кадром

- **Смена** живёт только в сессии браузера и на сервер не уходит.
  Если нужно, чтобы она переживала перезагрузку и была видна помощнику,
  это отдельная таблица.
- **Способ приготовления** у начинки не хранится, только ингредиенты.
- **Разбор слоёв** из текста не делается: парсер понимает список
  ингредиентов, а состав конфеты собирается руками.
- **Себестоимость** не считается — у ингредиентов нет цен.
